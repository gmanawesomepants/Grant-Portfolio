# Section Spec: SUIT SPEC SHEET

> Generated by /plan-section. Review and edit before building.

## Product Context

- **Job:** Translate the RevenueOS case study into a technical credential — using a dinner jacket blueprint as a visual analogy for system architecture, turning a software product into something a tailor would recognize.
- **Content Hierarchy:**
  1. Garment tag — `REVENUEOS · PATTERN I/III` (section label)
  2. Section heading — `System Blueprint`
  3. SVG dinner jacket — drawn on scroll via GSAP, stroke-dashoffset
  4. Callout lines — 8 technical specs mapped to suit anatomy (reveals sequentially)
  5. Closer — `Solo build. Currently in production.` (italic amber, fades in at end)
  6. Mobile fallback — spec list with amber left-border treatment (≤768px only)
- **Emotional Arc Position:** Visitors have seen the work cards (Pattern Book) and want proof. This section delivers it — not as a bullet list, but as a technical schematic. The medium IS the message: precision, detail, nothing superfluous.
- **Tailoring Metaphor:** A garment technical specification sheet. The jacket is both the product metaphor (bespoke system built to fit one client) and the literal vehicle for displaying architecture. Each callout line maps a tech component to a physical feature — the shoulder seam is your TypeScript stack, the breast pocket is your CI/CD pipeline.

## Design Direction

- **Fabric Texture:** Windowpane check — `repeating-linear-gradient` grid at 40px spacing. Vertical lines at `rgb(255 255 255 / 0.025)`, horizontal lines at `rgb(255 255 255 / 0.012)` (deliberately asymmetric — like real windowpane weave). Applied via `#suit-spec::before`, full-viewport-width, `z-index: -1`.

- **Background Layers (back to front):**
  1. `--color-bg` (#080808) — page base
  2. `#suit-spec::before` — windowpane texture, `z-index: -1`
  3. Section content (`isolation: isolate`)
  4. `.blueprint-svg-container` with SVG + HTML callout labels layered via `position: relative`/`position: absolute`

- **Animations — GSAP ScrollTrigger (scrubbed, pinned):**
  - Section pins to viewport; scroll controls timeline progress (`+=400%` scroll distance)
  - **Phase 1 (t=0–1.4):** Jacket outline draws in — body first, then sleeves simultaneously at t=0.3, then collar+lapels staggered starting t=0.6. Detail group (pockets, buttons, cuffs) fades in at t=1.4.
  - **Phase 2 (t=2.2–9.5):** 8 callouts reveal sequentially every 0.9 units — anchor dot → line extends → endpoint dot + label fade in.
  - **Phase 3 (t=9.2+):** Closer text fades in. Hold extends to t=10.
  - Hover system activates at `progress >= 0.98`: hovering a callout label or anchor hitarea dims all others via CSS `filter`, brightens active label to `--color-amber-light`, glow circle pulses at anchor point.
  - Desktop only (`window.innerWidth > 768`). Mobile: blueprint hidden, fallback list shown.
  - `scrub: 0.5` for smooth playback tied to scroll position.

- **SVG Jacket — Visual Spec:**
  - ViewBox: `0 0 400 500`
  - Stroke: `var(--color-amber)`, `stroke-opacity: 0.22`, `stroke-width: 1.5`
  - No fill anywhere — pure linework
  - Paths: body outline, left sleeve, right sleeve, collar, lapel left (outer + inner), lapel right (outer + inner)
  - Details: front closure (3 segments), breast pocket, 2 hip pockets, 2 buttons (outer + inner circle), cuff lines
  - Callout lines: `stroke-opacity: 0.35`, `stroke-width: 1`, amber

## Success Criteria

1. On desktop (>768px): jacket SVG draws completely in response to scroll before any callouts appear — no callout is visible while outline is incomplete.
2. All 8 callout lines extend from the correct anatomical point on the jacket to the correct margin, left/right assignment matching the CALLOUTS array.
3. Hovering a callout label or anchor hitarea dims all other callouts and brightens the active one — hover state is only active after scroll reaches ≥98% of timeline.
4. The closer text (`Solo build. Currently in production.`) is invisible until the final scroll phase and fades in cleanly.
5. On mobile (≤768px): SVG container is `display: none`, fallback list is visible with amber-dim left border and amber-trace background on each item.
6. Section pins during scroll animation and unpins cleanly when the timeline completes. After unpin, the section scrolls naturally with no visible jump, snap, or layout shift. The content below the section does not reflow.
7. Windowpane fabric texture is visible on close inspection but does not compete with the SVG linework.
8. `npm run build` passes with zero TypeScript errors.
9. The garment tag reads `REVENUEOS · PATTERN I/III` and the heading reads `System Blueprint`.
10. `cleanupBlueprint()` kills all ScrollTrigger instances and clears container HTML — no memory leaks on re-mount.

## Anti-Patterns

1. **Do not render the jacket as a static image or PNG** — the draw-on-scroll is the entire point; a static graphic defeats the metaphor.
2. **Do not use rounded card containers** around the blueprint — no borders, no backgrounds, no shadows framing the SVG.
3. **Do not add fill to any jacket path** — the jacket is a technical schematic, not an illustration. Fill destroys the blueprint quality.
4. **Do not list specs as a feature grid with icons** — that is standard SaaS layout. Specs belong on callout lines or the mobile list, nowhere else.
5. **Do not allow callout hover interactions to fire during scroll** — they activate only at `progress >= 0.98` to prevent accidental triggers while the animation is in progress.
6. **Do not change font to anything other than Syne for callout labels** — using Outfit here breaks the technical-drawing aesthetic.
7. **Do not skip the mobile fallback** — the SVG animation is desktop-only; mobile visitors must still see the specs.

## Dependencies

- `gsap` + `gsap/ScrollTrigger` — imported and registered in `suitBlueprint.ts`
- `initBlueprint` / `cleanupBlueprint` called from `page.tsx` `useEffect` with 500ms delay (allows DOM mount before GSAP queries)
- `.blueprint-svg-container` div must exist in the DOM before `initBlueprint` runs — it's the injection target
- `.suit-spec-closer` must have `opacity: 0` as its initial CSS state — GSAP animates it to 1
- `#suit-spec` must have `isolation: isolate` and `position: relative` for the `::before` texture and SVG stacking to work correctly
- Section ID must be `suit-spec` — both the animation and the CSS texture selector depend on it
