# Evaluation: HERO
**Date:** 2026-03-29
**Verdict:** ITERATE
**Weighted Score:** 64/100

## Scores
| Criterion | Score | Weight | Weighted |
|-----------|-------|--------|----------|

**Verdict rationale:** No criterion reaches 9+. Functionality scores 5 due to the cutting grid being a missing spec element (not a nitpick — the CSS exists, the element does not), a clock/scroll-indicator positioning collision, and one partial reduced-motion gap. Originality drops to 7 because the entire content block is center-aligned, which the spec's anti-pattern #1 explicitly flags. The weighted total is 64, below the 70 threshold for PASS.

## Design Quality — 8/10

The typographic composition is genuinely strong. `.hero-name` (globals.css:551-558) uses Syne 800 at `clamp(3.2rem, 8vw, 6.5rem)` with `-0.04em` letter-spacing and `line-height: 1.05` — these are deliberate, tight choices that create a sculptural mass on the page. The two-line name break ("Grant" / "Mahn") gives the name spatial weight that a single-line treatment would not.

`.hero-role` (globals.css:560-568) at `0.75rem / 500 / 0.25em letter-spacing / uppercase / amber` lands exactly as the garment tag it's meant to be. The amber here is earned — it's a single word against a field of near-black text, and the restraint makes it feel like hand-stitching on a dark lining.

The atmosphere layers are correctly stacked and at the right intensities. The breathing gradient (globals.css:480-497) is 800px at ~5% amber, confirmed `breathe` animation: `scale(1→1.2), opacity(1→0.5)` over 8s. The particle field opacity range of `0.08–0.35` (page.tsx:124) is quiet enough to register as gold dust, not a fireworks display.

The `.hero-dash` at `height: 1px, opacity: 0.5` (globals.css:578-583) is a beautiful breath of restraint between the tagline and mantra. At 40px, it's a tailor's mark, not a decorative flourish.

**What holds it from a 9:** The composition is centered — `.hero-content` uses `align-items: center` (globals.css:548) and `text-align: center` on the section (globals.css:445). The spec's Anti-Pattern #1 warns against "center everything and call it a day." The design is not *just* centered (the layering is intentional), but the content block itself is symmetrically centered with no spatial tension, no left-anchored weight, no deliberate asymmetry. For a brand referencing Savile Row — where nothing is placed without intention — this reads as the safe choice.

## Originality — 7/10

The hero passes several AI Slop Test criteria but fails on the one that most separates portfolio sites from a distinctive brand presence: spatial composition. Everything in `.hero-content` is center-aligned (`globals.css:445, 548`). The spec's anti-pattern #1 says "the composition should have spatial intention." Centered layouts are not inherently wrong — they're the default of almost every developer portfolio ever built. For a brand that references Dior, Saint Laurent, and latimer.me (a site with total compositional control), centering the entire text block is the safe choice. It reads as confident, not distinctive.

That said, the hero passes the AI Slop Test on the criteria that matter most:

1. The name reveal is `clip-path: inset(100% 0 0 0)` transitioning to `inset(0 0 0 0)` (globals.css:314-318). This is a curtain wipe from bottom up — not a fade-up. A template would never make this choice. Anti-Pattern #6 from the spec is explicitly avoided.
2. The mantra stagger ("Measured." / "Cut." / "Deployed.") at 380/480/580ms delays (globals.css:347-350) lands as three hammer strikes. The content itself — a tailor's process reframed as a deployment pipeline — is the kind of thing that stops a skimming visitor. It would not appear on another portfolio because no other portfolio has this identity.
3. The `.hero-pinstripes` implementation (globals.css:1994-2004) uses `repeating-linear-gradient(90deg)` at 40px repeat with `color-mix(in srgb, var(--color-text) 4%, transparent)`. The use of `color-mix` rather than a hardcoded rgba is a considered choice that respects the design token system.
4. The CTA button hover (globals.css:417-436) fills with amber via a `width: 0 → 100%` pseudo-element — amber wipes across to reveal the button filled, then text flips to `var(--color-bg)`. That's a deliberate fill-from-left mechanism, not `background-color: amber on hover`.
5. The custom cursor (globals.css:102-139) is a crosshair at 20px with 1px amber lines at 60% opacity — a measuring tool, a tailor's precision instrument. Not a dot, not a ring, not a gradient blob. This reads as intentional.

**What holds it from a 9:** The scroll indicator (globals.css:613-653) is functional but unoriginal — a 1px amber vertical line with "SCROLL" text. It does the job without surprise. The spec said "a whisper, not a shout" and it achieves that, but it doesn't use tailoring vocabulary (no "CONTINUE" or anything that reinforces the register of the brand).

## Craft — 7/10

The animation sequence is correctly spec'd and implemented. The three-stage load system works: stage 1 at 100ms (breathing), stage 2 at 400ms (particles), stage 3 at 900ms (clock, scroll indicator, `entered` classes) (page.tsx:472-475). The `entered` variable correctly appends class string to all animated elements.

The `ParticleCanvas` implementation (page.tsx:76-242) is genuinely well-engineered:
- Squared-distance check avoids `Math.sqrt` in the repulsion hot path (page.tsx:194)
- `ResizeObserver` on the parent instead of window resize event (page.tsx:163)
- `IntersectionObserver` pauses RAF when hero is off-screen (page.tsx:166-177)
- Particles rescale proportionally on resize rather than regenerating (page.tsx:147-154)
This is not boilerplate particle code. It shows care.

The `hero-anim-*` CSS classes use consistent `cubic-bezier(0.16, 1, 0.3, 1)` across all transitions (globals.css:316, 322, 328, etc.) — this is the "fast out, slow in" iOS spring easing that feels premium. Everything arrives with the same personality.

**What keeps this from an 8:**

1. **Missing cutting grid.** The spec (hero.md:26) specifies "Cutting grid (CSS, 1.5%) → Video → Breathing gradient → Particle field → Content" as the background layer order. The CSS for `.hero-cutting-grid` exists (globals.css:455-477) including a reduced-motion override that makes it visible (globals.css:1934-1936), but the element is never rendered in the JSX — there is no `<div className="hero-cutting-grid" />` in the hero section (page.tsx:506-539). This is a dropped atmospheric layer. Prefers-reduced-motion users see neither the animations they turned off *nor* the grid they were supposed to get.

2. **Clock has no horizontal anchor.** `.hero-clock` is `position: absolute; bottom: 2rem` with no `left` or `right` value (globals.css:598-607). Since the `.hero` section is a flex column with `align-items: center`, the clock renders centered at the bottom of the viewport, directly competing visually with the scroll indicator which is also centered at `bottom: 4rem`. Two centered bottom elements — clock and scroll indicator — create visual collision. The spec implies the clock should have a distinct corner placement to avoid this.

3. **Scroll indicator pulse range is slightly off.** The spec (hero.md:93) says `opacity 0.4 → 0.7 → 0.4`. The implementation pulses `0.25 → 0.55 → 0.25` (globals.css:651-653) — 0.15 dimmer on both ends. The whisper is slightly too quiet on entry.

## Functionality — 5/10

**Passes:**
- Clock updates every second at `America/Los_Angeles` via `setInterval` (page.tsx:322-335). HH:MM:SS format confirmed.
- Scroll indicator `display: none` at `max-width: 768px` (globals.css:655-658) — killed completely, not `opacity: 0`.
- `prefers-reduced-motion` disables all CSS animations and transitions, and forces all `entered`/`clip-path` states immediately (globals.css:1860-1952; page.tsx:471).
- `HeroVideo` gracefully hides on error (page.tsx:387-392, `display: hasVideo ? "block" : "none"`).
- Mobile font-size override: `hero-name` drops to `2.8rem` at 768px (globals.css:1799-1801).
- Skip-to-content link is present and keyboard accessible (page.tsx:501, globals.css:73-90).
- Particle canvas has `aria-hidden="true"` (page.tsx:241).

**Fails:**

1. **Cutting grid never renders** (as noted in Craft). This is both a craft issue and a functional one — there's dead CSS in the prefers-reduced-motion block pointing to an element that doesn't exist (globals.css:1934-1936 has `.hero-cutting-grid { opacity: 1 }` but no element receives it). Spec criteria #11 ("stage 1: grid + breathing") is partially failed.

2. **Clock centering conflict.** The clock at `bottom: 2rem` centered horizontally positions it directly under the scroll indicator at `bottom: 4rem` (globals.css:617). On a viewport, both elements occupy the bottom-center axis. This is a visual collision and a positioning bug — the clock should be anchored to a corner (right: 2rem is the natural choice).

3. **No mobile clock visibility check.** The spec doesn't call for hiding the clock on mobile, but with both the clock and scroll indicator absent/centered at narrow viewports, the bottom center becomes sparse. Not a blocking issue, but worth noting.

4. **The nav logo** uses `CONFIG.name + " " + CONFIG.lastName` rendered as plain text (page.tsx:360). The CLAUDE.md mentions a "needle-and-thread 't' logo in Italianno script" as a locked element. Either this hasn't been built yet or it's absent — the nav currently shows "Grant Mahn" in Syne 700 at 0.95rem, which is a reasonable fallback but not the specified brand mark.

## Success Criteria Check

1. "Visitor understands AI systems within 5 seconds" — **PASS.** "I build AI systems that actually work." as `.hero-tagline` is front and center. Clear.
2. "Name reads clearly on desktop (6.5rem) and mobile (2.8rem)" — **PASS.** `clamp(3.2rem, 8vw, 6.5rem)` desktop, `2.8rem` override at 768px.
3. "Breathing gradient visible but doesn't pull focus from text" — **PASS.** 5% amber intensity, 800px radial at correct z-index (1, below content z-index 3).
4. "Particles react to cursor movement (desktop only)" — **PASS.** `REPULSE_R = 150`, mouse repulsion math confirmed. No media query disables it on mobile since canvas handles its own geometry, but the `CustomCursor` disables at 768px. The particle canvas does not check window width — it runs on all screen sizes. This is a minor deviation from "desktop only" intent.
5. "Pinstripe texture visible in margins but invisible behind name" — **PARTIAL.** The pinstripes use `color-mix(in srgb, var(--color-text) 4%, transparent)` which is very subtle. The z-index of `hero-pinstripes` is 1 and `hero-content` is z-index 3, so content renders above. The 4% opacity is slightly stronger than the 0.025 opacity specified in CLAUDE.md for fabric textures generally.
6. "Clock updates every second, shows San Diego time" — **PASS.** Confirmed.
7. "Measured./Cut./Deployed. as three separate beats" — **PASS.** Three spans, 100ms stagger at 380/480/580ms. Confirmed.
8. "Scroll indicator desktop only, hidden mobile" — **PASS.** `display: none` at 768px.
9. "Total entrance completes briskly (~1.18s)" — **PASS.** Last element CTA at `transition-delay: 680ms` + 0.5s duration = ~1.18s total.
10. "Clip-path name reveal, not generic fade-up" — **PASS.** `clip-path: inset(100% 0 0 0)` confirmed.
11. "3 distinct load stages: (1) grid+breathing, (2) particles, (3) scroll+clock" — **FAIL.** Stage 1 does not include the cutting grid because the element is not in the JSX.
12. "prefers-reduced-motion disables animations, shows content, hides breathing+particles" — **PASS.** All handled in globals.css:1860-1952 and page.tsx:471.
13. "HeroVideo gracefully handles missing video" — **PASS.** Error handler sets `hasVideo: false`, element hidden.

## Top Issues to Fix

1. **[Functionality / Craft] Cutting grid element not rendered.** Add `<div className="hero-cutting-grid" aria-hidden="true" />` inside the hero section JSX, between the pinstripes div and the hero-breathing div (matching the spec's layer order: cutting grid → video → breathing → particles → content). The CSS at `globals.css:455–477` is fully defined and even has a reduced-motion override at `globals.css:1934–1936`, but no element receives it. This restores spec criterion #11 ("stage 1: grid + breathing") and activates the dead CSS.

2. **[Craft / Functionality] Clock has no horizontal anchor — collides with scroll indicator.** `.hero-clock` has only `bottom: 2rem` (`globals.css:599–600`). With `.hero` as a centered flex column, the clock renders at bottom-center, directly competing with the scroll indicator at `bottom: 4rem` (also centered). Add `right: 2rem` to `.hero-clock` to anchor it to the bottom-right corner. This gives it a grounding/realness function that matches the spec intent, and clears the visual collision.

3. **[Originality] Left-align the hero text block.** The single highest-impact change available. Move `.hero-content` to left-alignment — `align-items: flex-start`, `text-align: left`, position it in the left 55% of the viewport on desktop. Reserve the right side as negative space. This transforms the section from "confident center" to "spatially intentional" and is the difference between a Dior reference landing and it being aspirational only. On mobile, revert to centered. This alone would lift Originality to 9.

4. **[Craft] Scroll indicator pulse is 0.15 under spec.** Spec says `0.4 → 0.7 → 0.4`. Implementation uses `0.25 → 0.55 → 0.25` (`globals.css:651–653`). The `scroll-entrance` keyframe correctly lands at `opacity: 0.4`, then the pulse keyframe immediately drops it to `0.25`. Change `pulse-scroll` to: `0%, 100% { opacity: 0.4 }` / `50% { opacity: 0.7 }` — matching the spec and preventing the visual dip below entrance opacity.

## What's Working Well

**Design Quality (8):** The typographic scale is genuinely premium — the Syne 800 name with `-0.04em` tracking anchors the viewport, and the amber role label earns its color through restraint. The breathing gradient and particle field are calibrated correctly (neither element overwhelms).

**Originality — individual elements that earned their keep:** The clip-path curtain name reveal is a deliberate, memorable choice that would not appear in any template. The "Measured. Cut. Deployed." stagger lands as brand language, not a tagline. The CTA's fill-from-left amber wipe is a specific mechanism, not `background-color on hover`. The custom crosshair cursor as measuring tool is thematically coherent. These individual choices are strong — the issue is compositional, not elemental.

**Do not touch in iteration:** The name reveal, the mantra stagger timing, the particle system implementation, the amber usage density, the easing curves, or the atmospheric layer intensities. All are correctly tuned. The fix list above is surgical — missing element, anchor, pulse calibration, and layout axis. Nothing requires structural rebuild.
